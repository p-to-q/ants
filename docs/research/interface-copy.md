# Interface copy: discoveries with evidence

Use short phrases tied to observable states. Keep labels and buttons stable; do not rotate prose on a timer. Interest comes from model relationships and real discoveries. An evaluation failing does not mean a model is intrinsically bad, and a high development score is not a verified scientific win.

| phrase | evidence required | status |
|---|---|---|
| Cap leader | explicit retention reason identifies the selected within-cap development winner | Saved view implemented |
| Different route | explicitly retained core/route representative; need not be a winner | Saved view implemented |
| Worth a look | curated candidate with a recorded reason, not an automatic quality grade | Saved view implemented |
| Refit recorded | cached refit receipt; does not assert current file existence or a new score | Saved view implemented |
| Spec only | no recorded refit status | Saved view implemented |
| Pilot · exploratory | archive kind is pilot | Past implemented |
| Partial coverage | eligible results fewer than expected runs | Past implemented |
| A new best | a genuinely improved feasible result in the same scope/cap | use only an actual discovery event |
| Passed the torch | an explicit predecessor/successor best-model record | future transition view; not implemented |
| No clear winner | an accepted comparative analysis says so | future reviewed-study projection |
| Held as a comparison | selected weak or unusual route with a written rationale | future richer retention tags |
| Not retained | a recorded retention decision; evidence still preserved | future retention worker |

The four existing retained-collection cap leaders are pooled development selections. A different-core candidate may have a worse score and still be useful as a comparison. Do not call it a breakthrough or use a novelty score to disguise that distinction. Detailed reasons remain one Enter away.

Match the existing mint/grey palette and terminal hierarchy. Green indicates a measured or checked state with the appropriate scope; a bare off-host note is neutral. Missing, stale and failed receipts remain distinct. No jokes on failures, celebratory animations without events, judgemental “bad model” labels or unexplained “good” badges. Detailed repairs belong behind a concise actionable error.
